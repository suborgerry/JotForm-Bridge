
======================================================================
ЭТАП 5 — Auto Generate Renderer
===============================

Прочитай `AGENTS.md`.

Custom Template flow уже является рабочей базовой системой.

AutoRenderer должен быть только вторым способом rendering.

Он обязан использовать существующие:

* Integration;
* Normalized Schema;
* SubmissionValidator;
* SubmissionMapper;
* REST endpoint;
* frontend.js.

Не создавай отдельный submission pipeline.

---

# 1. AutoRenderer

Создай AutoRenderer, который строит form из Normalized Schema.

Главная задача:

* functional;
* semantic;
* accessible;
* easily stylable.

Не пытайся повторять дизайн Jotform.

---

# 2. Supported Fields

Рендерить только реально поддерживаемые normalized types.

Минимально:

* text;
* textarea;
* email;
* phone;
* number;
* select;
* radio;
* checkbox;
* full name;
* address.

Date — только если уже корректно поддержана schema/submission layer.

---

# 3. Semantic HTML

Использовать:

* `<form>`;
* `<label>`;
* `<input>`;
* `<textarea>`;
* `<select>`;
* `<fieldset>`;
* `<legend>`.

Каждый field должен иметь stable unique HTML ID.

Label должен быть связан с field.

Required field должен иметь соответствующую semantics.

Choice groups использовать `fieldset/legend`, где уместно.

---

# 4. data-jotform-field

AutoRenderer должен генерировать тот же frontend contract, что custom templates:

`data-jotform-field="email"`

`data-jotform-field="name.first"`

и т. д.

Таким образом существующий `frontend.js` должен работать без специальных веток AutoRenderer.

---

# 5. CSS hooks

Добавить predictable structural classes:

`.jfb-form`

`.jfb-field`

`.jfb-field--text`

`.jfb-field--email`

`.jfb-field--select`

`.jfb-field--checkbox`

`.jfb-error`

`.jfb-submit`

Не делать тяжелый default CSS.

Не навязывать design system.

---

# 6. Error hooks

Generated form должен содержать markup, который существующий frontend JS может использовать для:

* field errors;
* global form errors;
* success/error events.

Не создавать второй JS implementation.

---

# 7. Unsupported fields

Required unsupported field:

AutoRenderer не должен выдавать форму, которая заведомо не может корректно submit.

Покажи Administrator blocking diagnostic.

Frontend должен fail safely.

Optional unsupported fields:

могут быть skipped только с explicit warning/diagnostic.

---

# 8. Admin Integration

Если Rendering Mode = `auto`:

Template select должен быть irrelevant/disabled/hidden соответствующим образом.

Integration compatibility UI должен показывать:

* schema ready;
* unsupported required fields;
* auto renderer readiness.

Administrator должен иметь возможность переключить:

Custom → Auto

и:

Auto → Custom

без пересоздания Integration.

---

# 9. Accessibility

Проверить минимум:

* labels;
* unique IDs;
* required;
* radio group semantics;
* checkbox group semantics;
* errors with aria-live;
* keyboard accessibility;
* no JS-only labels.

---

# 10. Tests

Добавить render tests для:

* text;
* textarea;
* email;
* phone;
* number;
* select;
* radio;
* checkbox;
* full name;
* address;
* required;
* unsupported required.

Проверять не только наличие string, но и корректные field attributes.

---

# 11. MCP Verification

Playwright:

1. Сделать Integration Auto.
2. Открыть frontend.
3. Проверить generated markup.
4. Проверить keyboard/basic accessibility behavior.
5. Submit empty form.
6. Проверить errors.
7. Заполнить form.
8. Submit.
9. Проверить success.

Если test Jotform form доступна:

проверить настоящий end-to-end submission.

WordPress Playground:

* switching renderers;
* shortcode/helper;
* no fatal errors;
* no unnecessary API requests.

---

# Acceptance Criteria

Одна Integration может переключаться между:

Custom Template
и
Auto Generate

при этом submission pipeline остается одинаковым.

AutoRenderer использует исключительно Normalized Schema.

В конце укажи:

* какие normalized types AutoRenderer поддерживает;
* какие unsupported;
* accessibility checks;
* tests;
* MCP verification.

Не переходи к следующему этапу самостоятельно.
