# STAGE 3 — Integrations, Custom Templates and Template Validation

> **Historical.** This stage is finished. The file records what was asked for at
> the time, not what the code does now — some of it has since been overturned by
> the `Amendment:` sections in `AGENTS.md`. Read it for the reasoning, not as an
> instruction, and never as a description of current behaviour.

Read `AGENTS.md`.

Study the stage 1 and stage 2 implementation before changing anything.

The Normalized Schema is an internal contract that already exists. Do not create
a second, alternative schema representation.

Do NOT implement in this stage:

* frontend JavaScript;
* the public REST submission;
* sending submissions to Jotform;
* SubmissionMapper;
* AutoRenderer.

The goal of the stage:

Jotform Form
+
Integration
+
Custom PHP Template
+
Schema Compatibility

## 1. Integration

Create a domain and repository layer for Integration.

An Integration holds at least:

* name;
* slug;
* Jotform Form ID;
* rendering mode;
* template slug;
* active status.

Rendering modes:

`custom`

`auto`

At this stage `auto` may be stored as configuration; AutoRenderer is not to be
implemented yet.

The slug has to be:

* sanitized;
* unique;
* used as the public local identifier.

For example:

`contact`

Theme code must never need a Jotform Form ID.

> Superseded: the `active` flag was dropped. An integration either exists or it
> does not.

## 2. Integration storage

Use WordPress options. Do not create a custom DB table.

The repository is responsible for:

* list;
* get by slug;
* create;
* update;
* delete;
* uniqueness validation.

Do not scatter direct `get_option` / `update_option` calls through the plugin.

## 5. The custom template directory

The main path:

`/forms/`

in the active theme. For example:

`wp-content/themes/example/forms/contact.php`

Take into account:

* a child theme;
* a parent theme.

The child theme has priority.

Add a filter:

`jotform_bridge_template_paths`

for additional directories.

Do not support Sage or Blade. PHP templates only.

> Superseded: the directory is `jotform-bridge-templates/`, not `/forms/`.

---

## 6. Template metadata

A template is identified by its header:

```php
<?php
/*
Jotform Template Name: Contact Form
Jotform Template Slug: contact
*/
```

Required values:

* Jotform Template Name
* Jotform Template Slug

This must not be used:

`Jotform Form ID`

in template metadata. A template has to be completely independent of any
particular Jotform Form.

> Superseded: the slug is the file name. The `Jotform Template Slug` header is
> ignored, with a warning.

---

## 7. TemplateScanner

Create a `TemplateScanner`. It has to:

* resolve the permitted paths;
* find PHP files safely;
* read only as much of the source as it needs;
* extract the header metadata;
* never execute PHP;
* reject invalid metadata;
* detect duplicate slugs;
* honour child theme priority;
* prevent directory traversal;
* return diagnostics.

Do not scan the filesystem on every page request.

---

## 8. TemplateRegistry

Cache the result of discovery. An entry, roughly:

```php
[
    'slug' => 'contact',
    'name' => 'Contact Form',
    'file' => '/trusted/theme/path/forms/contact.php',
]
```

The runtime renderer will later be able to use a registered entry and nothing
else. An arbitrary file path is forbidden.

> Superseded: the registry is not cached between requests. See "Amendment:
> template discovery reads the theme on demand".

---

## 9. Rescan Templates

Add an admin action:

`Rescan Templates`

It has to:

* invalidate the registry;
* scan again;
* store the registry;
* show the result.

For example:

`3 templates found`

or diagnostics about a duplicate or invalid header.

> Superseded: removed along with the registry cache.

---

## 10. Template field discovery

For compatibility validation, extract the literal values of:

`data-jotform-field="..."`

from the source. For example:

`email`

`name.first`

`name.last`

Do not execute the template, and do not try to evaluate dynamic PHP:

```php
data-jotform-field="<?php echo $something; ?>"
```

Where a field identifier is dynamic, the static validator must not guess at it.
A warning is acceptable:

`Dynamic field identifier cannot be statically validated.`

---

## 11. TemplateValidator

Create a separate validator:

Template fields
vs
Normalized Schema

It reports:

* matched;
* required schema field missing;
* optional schema field missing;
* unknown template field;
* unsupported required schema field;
* unsupported optional schema field;
* dynamic/unverifiable field.

Statuses:

`Compatible`

`Compatible with warnings`

`Invalid`

The rules:

A missing required field → Invalid.

An unknown template field → Invalid.

A missing optional schema field → Warning.

An unsupported required field → Invalid, or an explicit blocking diagnostic.

---

## 12. Composite validation

The validator has to handle paths correctly:

`name.first`

`name.last`

`address.city`

and so on.

The presence of `name` is not enough where the template actually has to contain
particular required children. Use the structure of the Normalized Schema.

---

## 13. Schema refresh

On the Integration edit screen, add:

`Refresh Schema`

Pressing it:

1. fetches the current Jotform schema;
2. normalizes it;
3. stores the new cached schema;
4. computes the fingerprint;
5. runs TemplateValidator again;
6. updates the compatibility state.

Tell the administrator whether the schema changed.

> Superseded: the action is called **Sync Schema**, and the result is stored
> rather than cached.

## 17. MCP verification

WordPress Playground:

1. Use a test theme.
2. Create `/forms/contact.php`.
3. Run Rescan Templates.
4. Check the registry.
5. Create an Integration.
6. Bind the cached/test Jotform schema.

Playwright:

1. Open Integrations.
2. Create an Integration through the UI.
3. Pick a Jotform Form.
4. Pick a custom template.
5. Check the compatibility.
6. Deliberately remove a required `data-jotform-field` from the test template.
7. Rescan / Refresh.
8. Confirm the status becomes `Invalid`.

Do NOT perform a Jotform submission at this stage.
